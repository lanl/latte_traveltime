
We currently only provide traditional Makefile-based approach to compile `LATTE`:

* To compile, set the path to `FLIT` with `flitdir = ...` in [Makefile](2d/Makefile) and [Makefile](3d/Makefile), or run `ruby install.rb flitdir=...`; the default path to `FLIT` is `$HOME/src/flit`. `ruby install.rb` passes each argument `name=value` to `make`, which overrides the variable `name` in the Makefiles. 
* To use legacy eikonal solvers, enable `-Dlegacy_solver` in [Makefile](2d/Makefile) and [Makefile](3d/Makefile); the default is not using legacy solvers. 
* To also build CUDA versions of the 3D executables, run `ruby install.rb clean use_cuda=on`, or set `use_cuda = on` in [Makefile](3d/Makefile); the default is off. Besides `x_eikonal3`, `x_fatt3`, `x_trtt3` and `x_tloc3`, which run on the CPU as before, the build then makes `x_eikonal3_cuda`, `x_fatt3_cuda`, `x_trtt3_cuda` and `x_tloc3_cuda`, which solve the eikonal and adjoint-state equations on GPUs and take the same parameter files. This needs `nvcc` of the CUDA Toolkit. `cuda_arch` sets the GPU architecture, e.g., `sm_80` or `sm_90` (`nvcc --list-gpu-arch` lists the values); the default, `native`, targets the GPU of the build machine. For example, `ruby install.rb clean use_cuda=on cuda_arch=sm_80` compiles for the architecture `sm_80`. `cuda_home` sets the CUDA Toolkit directory whose `lib64` holds the CUDA runtime library, when it is not the parent of the directory of `nvcc`. Use the same options in every later `ruby install.rb`, so that the CUDA executables stay up to date, and add `clean` when they change, because `make` does not recompile the objects after an option change. With `-Dlegacy_solver`, only the adjoint-state solver runs on GPUs.
